# Data Integration & Live Streaming (Polymarket Screener)

This document describes the unified data models and real-time integration layer that power the **Polymarket Screener**. It ensures that disparate data from multiple exchanges are processed into a single, high-fidelity stream for the quantitative engine.

---

## 📊 Core Data Types (`app/core/domain_models.py`)

The system enforces strict typing for all market data to prevent "NoneType" errors in math layers.

### 1. `MarketSnapshot`
The primary atomic unit of data. Every engine tick is a `MarketSnapshot`.
*   **`market_id`**: Unique identifier (e.g., BTC-WIN-2024).
*   **`spot_price`**: Current underlying price (from Binance).
*   **`implied_vol`**: Annualized IV percentage (from Deribit DVOL).
*   **`polymarket_yes` / `polymarket_no`**: Real-time mid-prices from Polymarket CLOB.
*   **`orderbook`**: A `UnifiedOrderbook` object containing bids/asks for liquidity scoring.

### 2. `TradeSignal`
Generated by the `MarketScreener` when a mathematical edge is detected.
*   **`side`**: `BUY_YES` or `BUY_NO`.
*   **`target_price`**: The Black-Scholes "Fair" probability.
*   **`edge`**: `Fair - Market`.
*   **`allocation_pct`**: Suggested Kelly-scaled position size.

## 📡 Live Integration Layer (`app/core/data_feed.py`)

The system uses a **Search-First Ingestion** strategy, preferring WebSockets for speed with REST fallbacks for reliability.

### 1. Unified Client Interface
All exchange clients inherit from `BaseExchangeClient`, providing:
*   **`check_health()`**: Automatically marks a client as "Unhealthy" if data is stale for >180s.
*   **`mark_update()`**: High-precision timestamping for latency tracking.

### 2. WebSocket Orchestration
The `app/main.py` entry point initializes three concurrent WebSocket streams:
*   **Polymarket CLOB WS**: Streams orderbook increments.
*   **Binance Spot WS**: Streams 1m klines and real-time tickers for `BTC/USDT` and `ETH/USDT`.
*   **Deribit DVOL WS**: Streams the "Crypto VIX" (DVOL) for real-time volatility inputs.

### 3. The Feed Aggregator
The `FeedAggregator` class performs the "Join" operation:
1.  Listens to all active WebSockets.
2.  Caches the latest values for Spot, IV, and Book.
3.  On every Polymarket update, it packages the cached Spot/IV into a `MarketSnapshot` and publishes it to the internal **Event Bus**.

---

## 🔐 Authentication & Private Streams
For live execution, the system supports **EIP-712** signing via the `py-polymarket-clob-client`:
*   **Private User Channel**: Subscribes to fill notifications and balance updates.
*   **Signature Header**: All WebSocket connections for authenticated accounts include an `auth` type message with an HMAC signature.

---

## ⚡ Latency Strategy
*   **Vectorization**: The math engine (`BlackScholes`) processes arrays of snapshots via NumPy to minimize Python loop overhead.
*   **Non-Blocking I/O**: Entirely powered by `asyncio`. The processing of a signal does not block the receipt of the next market tick.
*   **Pre-Warm Phase**: The `EngineClock` maintains a 120s pre-warm buffer to ensure correlation trackers have enough data before emitting signals.
