### Chat-style command input (new default entry point)
- `backend/cli/tui/chat_parser.js` — deterministic, no-network resolver. Hardened against a real
  false-positive: a short token like "ate" was spuriously matching mid-word inside "str**ate**gy"
  and would have silently run a real command on garbled input — now requires a prefix match before
  falling back to substring matching.
- `backend/cli/tui/chat_llm_fallback.js` — local Ollama fallback (reuses `ai_client.js`, no new
  dependency) for input the deterministic parser can't resolve. Validates every field against the
  real manifest before use; degrades safely when Ollama is unavailable.
- Both paths route through one shared `runOrGatePin()` so the `--live` PIN gate applies identically
  regardless of how a command was produced. **Real bug caught while wiring this up:** the PIN
  view's render was gated on the grid's own `cmd` selection (`drilled = ... && !!cmd`), which is
  always `null` for a chat-resolved command — the gate's *state machine* worked, but the UI
  silently failed to render. Fixed by making `pinView` a standalone view reading from `pendingRun`.
- **UX iteration, mid-session:** first built as a full alternate "SOVEREIGN CHAT" page (title,
  instructions, scrolling transcript) that replaced the grid when active. User's reaction: "why is
  there a whole another section, why can't you just add the chat section as a bar underneath?"
  (shared a screenshot of Claude Code's own terminal status bar as the reference). Rebuilt as a
  thin single-line bar underneath the always-visible grid; results now route through the existing
  Output panel's status line instead of a parallel transcript. **Saved to memory**
  (`feedback_minimal_tui_bars.md`): default to minimal single-line bars for new TUI affordances,
  not boxed sections with titles/instructions, unless explicitly asked for a distinct page.
- **Chart width bug** (`backend chart --width` / live-chart mode): `renderPriceChart()` didn't
  account for its own ~12-char label/border overhead, so `--width` past ~90 on a ~100-col terminal
  wrapped every row mid-line and visibly broke the grid. Fixed by clamping to
  `process.stdout.columns` inside `renderPriceChart()` itself (single fix point, benefits every
  caller).
- **Typing lag on PowerShell, diagnosed but not fixed:** classic `conhost.exe` console (not
  Windows Terminal) — every keystroke triggers a full Ink re-render of the entire multi-line
  screen (sidebar+content+output+bar+footer), requiring multi-line cursor-up ANSI movement, which
  is the exact category of sequence that's flaky on that console host. User correctly pushed back
  on "just switch terminals" by asking why Claude Code's own CLI doesn't have this problem — answer:
  Claude Code's input almost certainly does a single-line `\r`+clear-to-EOL redraw, never needing
  multi-line cursor movement at all. **Real fix (deferred, user-approved):** isolate the chat bar's
  per-keystroke redraw from the full-tree Ink reconciliation. Documented inline in
  `sovereign_dashboard.mjs` next to the `chatBar` definition.
- **Chart upgrade, deferred (user-approved):** researched `terminus` (uses TradingView's
  lightweight-charts: candlesticks, volume histogram, crosshair, MA/indicator overlays) and the
  vendored `lightweight-charts` library itself for feature-set inspiration (not code reuse — it's
  canvas/browser-based). Confirmed cached bars already carry full OHLCV, so candlesticks (low
  effort) + a volume subplot (medium) + an SMA overlay (medium) are all feasible in ANSI. Ranked
  and documented inline next to `renderPriceChart()`.

### Process-leak incident (caught and fixed, not just noted)
Repeated test re-runs of the PIN-gate tests left **8 real `sovereign_cli.js auto-trade --interval
15 --live` child processes running** — `handleRun`'s real spawn fires regardless of a test's
mocked `onRun`, and a bounded "wait then maybe abort" pattern isn't reliable if the
`ai_agent_trading` feature flag is enabled. Killed all 8 (user-confirmed via AskUserQuestion before
any `taskkill`, since this is a live-trading platform). Hardened both PIN-gate tests (the existing
one in `sovereign_dashboard.test.js` and the new one in `chat_ui.test.js`) to unconditionally abort
via Escape after confirming the PIN, not conditionally on a timeout.
