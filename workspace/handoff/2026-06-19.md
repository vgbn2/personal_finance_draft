# Handoff — 2026-06-19

## Update - 2026-06-19 session 39 (cont.) — first real GitHub backup of personal_finance_draft (subtree-split push)

User asked to "sync it all". Investigation + execution, in order:

**1. Clarified "sync" target.** Two candidate meanings: the long-standing Ubuntu LAN sync carryover
(blocked — Windows `sshd` is `Stopped`/`Manual`, starting it needs elevated PowerShell I don't have;
Ubuntu machine power state unknown) vs. a GitHub push. User picked GitHub, "all real branches" (`main`,
`feat/session-guard-intraday-rollup`, `feat/ml-onnx-section`, `feat/resilient-crypto-fallback`) —
explicitly excluding the 5 disposable `worktree-agent-*` branches (isolated-agent-tool leftovers, all
at the same commit `be96d76c`).

**2. First surprise — wrong git root.** `git rev-parse --show-toplevel` from inside
`personal_finance_draft/` resolves to the **CODEPTIT monorepo root**, not this subdirectory. A plain
`git push origin main` therefore tries to push *every* sibling project (MiroFish, `_tools/`, `heroku/`,
research notebooks, practice files, etc.), not just the trading platform. GitHub's pre-receive hook
rejected it on a 166MB `_tools/automation_n8n/talkytimes/Antigravity.exe` (hard 100MB limit) — nothing
to do with this project.

**3. Second surprise — origin already has divergent history.** `origin` (`vgbn2/personal_finance_draft`
on GitHub) already had `main` and `feat/session-guard-intraday-rollup` branches, both at commit
`be96d76c`, rooted at `524e787d` — a completely unrelated commit graph from local's `815c7c5d`-rooted
history (no common ancestor). Despite the disjoint history, the *content* clearly overlaps (origin's log
mentions the same "session 33... TUI cleanup + Ubuntu SSH deferred" work this repo's own session memory
describes) — these are two real, independently-evolved timelines from roughly the same starting point,
each since deepened by genuine, distinct commits (origin has "backfill-daemon parallel provider lanes",
"add clear-api-cache command"; local has all of sessions 34-39's FW2/recovery/vintage-audit work).
Neither side is disposable. Force-pushing would have permanently destroyed whichever side lost.

**4. Resolution (both confirmed by the user via AskUserQuestion):**
- Push under new branch names (`local-*`) rather than overwrite origin's existing branches — origin's
  `main`/`feat/session-guard-intraday-rollup`/`draft` are completely untouched.
- Scope the push content to *only* the `personal_finance_draft/` subtree, not the whole monorepo — used
  `git subtree split --prefix=personal_finance_draft <branch> -b <new-branch>` (must run from the
  monorepo toplevel, not from inside the subdirectory — `subtree split` refuses otherwise). 327 total
  monorepo commits / 178 on `main` made this fast (well under a minute per branch); `git filter-repo`
  wasn't installed and wasn't needed at this size.
- Pre-flight checked the 4 new subtree-only histories for oversized blobs before pushing (`git rev-list
  --objects ... | git cat-file --batch-check`) — found nothing above ~21MB
  (`storage/data/cache/backtest_history.json`, several historical copies), comfortably under both the
  50MB warning and 100MB hard limit.
