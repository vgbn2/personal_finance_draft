### Root Cause
The dominant write volume comes from binary TS full-rewrite when `tryAppendBin` fails due to timestamp overlap. Normal incremental backfill fetches recent bars that overlap the tail of existing data. `tryAppendBin` (L213) checks `incoming[0].ms <= lastTimestamp` — any overlap at all causes fallthrough to the C++ merger which rewrites the entire 100+ MB file.

## Implementation Update — 2026-10-21

Implemented the approved SSD write optimization sequence:

- `TS-APPEND-OVERLAP`: duplicate tail records are compared from the binary index and skip full native merge rewrites; newer records retain the fsync-protected append path; conflicts retain provider-priority merge behavior.
- `JSON-WRITE-COMPACT`: six machine persistence writers now use compact JSON without changing parsed values, atomic replacement, locks, or file modes. Structured human-readable JSON assembly in `validation.js` was intentionally left unchanged.
- `BACKFILL-JSON-POLICY`: public `mass-backfill --binary-only` skips legacy JSON history while retaining TS index and quality-report writes; default behavior is unchanged.
- `RUNTIME-TELEMETRY-COALESCE`: each loop tick now emits one final status and heartbeat write, preserving startup, stop, retry, degraded, and crash state semantics.
- `TS-MERGER-IO`: native merger buffers are heap-backed at 65,536 records (~3 MiB per stream) instead of stack-backed 1,024-record buffers. Descriptor-level fsync remains deferred because the current cross-platform stream abstraction has no verified portable descriptor boundary.
