# Handoff - 2026-07-10

## Update - 2026-07-10 session 68 - always-on backfill and scorecard host

Implemented the deployment-facing scorecard surface before host selection. `/api/scorecard` now runs
the existing scorecard calculation in a worker thread against the host-local ts-index, returns structured
metadata and rows, deduplicates identical concurrent requests, and caches results for 30 seconds. The
route requires `SOVEREIGN_API_TOKEN`; CLI `scorecard --json` retains its established raw-array contract.

The existing Docker Compose `web` plus `backfill` shape is the target runtime. Added always-on env
defaults and deployment instructions. The daemon now prunes expired disposable API-response cache files
at every cycle and caps retained fresh entries at 25,000; canonical `storage/data/ts/` files are never
pruned. The existing ~28 GB provider cache was measured but deliberately not deleted.

Measured locally: all-universe scorecard 7.08 seconds, 167,340 KB max RSS, ~106% CPU; crypto-only API
request completes in roughly 2.4 seconds. Current storage is ~30 GB total and ts-index is ~4.1 GB. The
full backfill is the sizing constraint because its container has a 6 GB V8 heap ceiling for concurrent
1-minute merge writes. Cheapest defensible full-universe host: 2 shared vCPU, 8 GB RAM, 80 GB SSD.
Recommended low-cost headroom: 4 vCPU, 12-16 GB RAM, 120-160 GB SSD. No GPU is used.

Verification passed: authenticated/unauthenticated scorecard API and cache behavior, invalid query
handling, non-blocking health behavior, authenticated CORS preflight, backfill-daemon regression tests,
provider-cache pruning test, frontend production build,
scoped `git diff --check`, and `npm run hygiene`. Docker Compose validation could not run because this
machine has no `docker` executable. `graphify` is also unavailable. Before deployment, install Docker,
set a strong API token, run `docker compose -f infra/docker/docker-compose.yml up -d --build web backfill`,
and keep port 8787 behind an SSH tunnel/private VPN. Run the existing cache deletion only with explicit
approval if reclaiming the current 28 GB is desired.
