# Handoff - 2026-07-12

## Update - 2026-07-12 session 74 - focused TUI and Polymarket lifecycle review

Completed a review-only pass over the Ink dashboard input bar, viewport density, Polymarket ended
positions, and the maintainability of the affected code. Full ranked evidence and grades are in
`workspace/DEV_REVIEW.md` under "Focused TUI, Polymarket Lifecycle, and Maintainability Review".

Confirmed defects:

- The bottom command bar accepts ordinary characters, end Backspace, Enter, Tab focus, and PIN flow,
  but mid-line Left/Right editing is broken because `TextInput` is rendered with `showCursor:false`,
  which disables its logical cursor movement in the installed version.
- The TUI has no responsive viewport policy. Its fixed 20-column menu plus 76-column content produces
  a 100-column body in an 80-column PTY and collapses the output pane into vertical character noise.
- Height resize is non-reactive: a dashboard mounted at 30 rows still emitted 28 rows after resize to 12.
- Live Polymarket positions are reconstructed from fills; resolved metadata is fetched only for labels,
  then discarded. Ended shares can remain under "Active Positions" at cost-basis fallback value and
  contaminate aggregate equity.
- Polymarket quote handling temporarily replaces process-global `console.error` without `try/finally`.
- The modern and legacy TUI manifests have 51 versus 49 commands plus 11 shared flag-schema drifts;
  the modern `App` is about 957 lines with 25 state hooks.

Verification:

- Focused dashboard/chat tests passed 19/19.
- Real 80-column PTY and controlled 80/100/120/140/160 width probes reproduced the layout threshold.
- Direct input probes confirmed end Backspace works and mid-line cursor editing does not.
- Controlled 30-to-12-row resize reproduced stale height.
- No production code or live external API state changed.
- `graphify-out` is absent, so no graph refresh was possible.

Recommended next implementation order:

1. Add pure Polymarket lifecycle fixtures and stop ended/unknown rows from entering active holdings or
   marked equity without verified resolution value.
2. Extract a display-width-aware `CommandInput` and pure viewport policy with edit/resize/80-column tests.
3. Apply responsive breakpoints and trim redundant borders/rules based on those contracts.
4. Canonicalize the modern and legacy command schemas, then split dashboard process/controller/render
   responsibilities while behavior is test-locked.
